01

콜로세움에서 가져올 것은 고객의 선택 과정

아래 ‘확인 사실’은 공개 페이지의 구성·안내 문구입니다. 실제 추천 품질이나 사업 성과를 검증한 것은 아닙니다.

공개 페이지에서 확인한 것기획적 해석GNG 적용안
이커머스·B2B·크로스보더 등 업무별 서비스 진입콜로세움 홈페이지고객이 자신의 사업을 기준으로 서비스를 찾게 함출입·관제·시설운영·공간·대피안전·물류 문제를 첫 진입 메뉴로 제공
물류 IT, 전문 담당자, 고객 사례를 함께 설명서비스·전문가·사례 구성시스템 기능과 실제 운영 지원을 함께 이해시킴제품 조합뿐 아니라 현장조사·시범 적용·교육·운영 지원 범위까지 제안
요금 항목·청구 예시와 3개 조건의 간단 계산 제공요금 안내 · 간단 계산상담 전에 비용을 이해할 단서를 제공초기에는 비용 항목·산정 기준·포함/제외 범위 공개. 승인된 단가표 확보 후 조건부 범위 견적 도입
Vault는 진단 → 추천 → 현장 맞춤 제안 → 리포트 흐름 소개Vault 솔루션 서비스고객 현황을 제안의 입력으로 구조화GNG의 여러 제품군을 공통 진단으로 연결하고, 문제별 후속 질문으로 전문 상담 준비
GNG만의 초점: 출입 → 공간 이용 → 현장 업무 → 이상 감지 → 대응·운영까지 연결할 수 있는 제품 구성을 활용합니다. 고객에게는 하나의 담당 창구를 제공하고, 실제 연동과 수행 범위는 제안 단계에서 확정합니다.
Vault의 10개 문항과 추천 데이터에서 확인한 설계 원리

운영 유형 → 취급 상품 → 운영 환경 → 출고 형태 → 어려운 공정 → 자동화 목적 → 현재 시스템 수준 → 연동 환경 → 센터 규모 → 일 평균 주문·출고량을 묻습니다. 첫 질문은 브라우저 렌더링, 전체 문항은 화면이 사용하는 공식 공개 질문 데이터로 확인했습니다.

공식 추천 데이터에는 제품 조합·적합 조건·제외 조건·예시 KPI가 있습니다. 이 구조에서 참고할 점은 고객의 목표와 현장 제약을 함께 확인한다는 것입니다. 답변 제출, 추천 결과 생성, 리포트 발송은 실행하지 않았습니다.

FOR YOU는 고객 조건별 대응을 소개하는 정적 페이지이고, 진단은 Vault에 별도로 있습니다. 본사 문의에는 담당 FD와 영업일 2일 이내 연락 안내가 있어 접수 이후 기대를 명확히 합니다. GNG의 응답 약속은 자체 운영 역량에 맞춰 정합니다.

물류 요금 계산식을 건물·안전·설비 프로젝트에 그대로 적용하거나, 홈페이지의 절감률을 GNG 예상 효과로 옮기지 않습니다. GNG가 물류 보관·배송 대행을 제공한다는 근거도 이번 조사에서는 확인하지 못했습니다.

04

진단에서 실제 제안까지 끊기지 않는 흐름

설문 결과를 상담자가 다시 묻지 않도록 전달하고, 초기 추천과 최종 제안의 차이도 기록합니다.

01 · 발견

고민으로 시작

문제 카드·업종별 랜딩·사례에서 진입. 제품을 아는 고객은 제품 목록으로 바로 이동.

02 · 진단

공통 질문 6개

현장 유형, 최우선 문제, 적용 규모, 현재 운영 방식, 도입 목표, 희망 시기. 모름 허용.

03 · 이해

바로 보는 검토안

최소 구성, 선정 이유, 도입 조건, 다음 확인 항목. 로그인·연락처 없이 결과 조회.

04 · 상담

진단 결과 전달

상담 요청 시 담당자 이름·업무 이메일과 필요한 회사 정보를 수집. 보완 질문과 담당자 배정.

05 · 실행

범위·지표 합의

표준 적용은 견적·구축으로 진행. 현장·연동 불확실성이 있으면 별도 진단·시범 적용 후 결정.

문제별 상세 질문은 결과를 보여준 후 필요한 만큼 수집

온라인 보완 질문은 해당 문제에서 중요한 항목 최대 2개부터 제시하고, 상세 자료는 상담 과정에서 받습니다.

  • 출입: 방문자 수·유형, 사전 승인 절차, 기존 출입통제 제조사·인터페이스.
  • 관제·안전: 장비·센서 목록, 도면, 이벤트 종류, 대응 담당자와 운영 시간.
  • 시설·에너지: 자산·점검표·민원 처리 흐름, 계측 데이터, 제어 가능 설비.
  • 공간: 회의실·좌석 수, 예약 시스템, 일정 연동 조건, 활용률 측정 방법.
  • 물류: SKU·입출고량·피크 물동량, 치수·하중·건물 조건, WMS/WCS 인터페이스.
  • 예산은 ‘미정’ 허용. 현장 도면·운영자료 업로드는 담당자와 필요 범위를 합의한 후 진행.
추천 결과 1장에 꼭 담을 항목

고객 조건 요약 / 우선 해결 문제 / 먼저 할 업무 / 핵심 구성과 선정 이유 / 선택 확장과 제외 이유 / 기존 시스템 활용 조건 / 제공 상태 / 검증할 효과와 필요한 기준 데이터 / 비용 항목 / 담당자와 다음 단계.

같은 조건에 항상 같은 후보가 나오도록 추천 규칙과 제품 카탈로그의 버전을 남깁니다. 현장 적합성을 확인하지 못하면 ‘추가 진단 필요’로 안내합니다.

05

직접 선택해 보는 진단·제안 시안

실제 서비스 개발 전, 고객에게 제시할 정보와 분기 방식을 검토하는 로컬 시안입니다.

우리 현장에 맞는 시작점 찾기

6개 항목을 선택하면 검토할 구성과 다음 확인 사항이 달라집니다.

기획 시안 · 입력 외부 전송 없음

시안에서는 선택값만으로 규칙을 적용합니다. 실제 제품 가용성 조회·가격 산정·AI 분석·상담 접수·고객정보 저장은 연결하지 않았습니다. 결과를 새로 생성하거나 텍스트로 저장할 수 있습니다.

06

설명할 수 있고 과잉 제안을 줄이는 추천 규칙

초기 제품은 규칙·카탈로그 기반으로 만들고, 자유문장 해석은 상담 데이터가 쌓인 뒤 보조 기능으로 추가합니다.

핵심 제품을 고르는 순서

  1. 제공 가능성 확인: 제품 상태·적용 산업·필수 연동·하드웨어 조건으로 후보 자격 확인. 모르는 조건은 검토 대기로 표시.
  2. 문제와 직접 연결: 최우선 문제를 해결할 최소 구성 1개를 우선 제시. 필수 장비가 있을 때만 묶음.
  3. 중복 방지: Smart FM과 SSAx의 FMS 기능 중복을 설명하고 역할·데이터 책임을 정함.
  4. 확장은 이유가 있을 때: 두 번째 문제, 기존 데이터 연결 또는 실행 장치의 필요가 확인된 경우에만 추가.
  5. 불확실하면 진단: 임의 적합도 점수나 확정 가격 대신 부족한 정보와 확인 방법을 제공.

제품 카탈로그가 갖춰야 할 데이터

문제: 해결 업무·적용 대상·핵심 가치·제외 범위

준비 상태: 기능별 제공 상태·확인일·담당자·근거 문서

조건: 장비·통신·API·설치·데이터 요건과 연동 검증 결과

제안: 필수/선택 모듈·중복 기능·가격 산정 단위·운영지원 범위

증거: 공개 가능한 실제 사례·측정 조건·고객의 공개 허용 범위

안전 제어·공공 안전망 연계는 기능 소개만으로 가용성을 판단하지 않고, 현장·수행 범위를 확인하는 별도 검토 경로를 둡니다.

07

매출은 진단 이후의 실행에서 발생

진단 서비스는 초기 상담을 돕고, 상세 설계·구축·운영은 범위와 산정 기준을 분리해 계약합니다.

무료 · 진입

온라인 진단·기본 상담

조건 정리, 구성 후보, 준비자료 안내. 고객은 내부 검토용 요약을 가져갑니다.

초기 상담 시간·제공 범위를 운영 정책으로 정해 무제한 설계 요청을 방지합니다.

프로젝트 · 도입

현장 진단·시범 적용·구축

현장 조사와 상세 설계, 제한된 범위의 PoC, 연동·장비·설치·교육을 각각 견적.

시범 적용의 성공 기준·산출물·본 구축 전환 조건을 시작 전에 합의합니다.

반복 수익 · 운영

사용료·유지관리·개선 지원

제품별 구독/라이선스 가능 여부를 확인한 후 사업장·사용자·장비 등의 산정 단위를 확정.

현장 대응, 정기 점검, 소프트웨어 유지보수와 추가 개발의 경계를 명시합니다.

가격 화면 제안: 초기 구축비(현장 분석·설정·연동·장비·설치)와 반복 비용(사용료·유지관리)을 나누고, 출장·공사·기존 벤더 연동비 등 제외 항목을 설명합니다. 금액은 내부 승인 단가표와 실제 견적 데이터가 준비된 뒤 공개합니다.

이미 제공·연동 조건이 확인된 표준 구성은 견적으로 바로 진행할 수 있습니다. 모든 고객에게 유료 현장 진단이나 PoC를 필수로 부과하지 않습니다.

ROI를 제공할 때는 고객의 실제 기준 데이터와 도입 후 운영비를 반영합니다. 회수기간 예시는 초기 투자비 ÷ 월 순편익으로 계산하되 월 순편익이 0 이하라면 회수기간을 제시하지 않습니다. 절감 가능 작업시간을 곧바로 현금성 인건비 절감으로 계산하지 않습니다.

08

홈페이지와 영업 업무를 함께 설계

고객 화면만 만들고 끝나지 않도록 담당자에게 넘어가는 정보와 상태를 정합니다.

사이트 메뉴 제안

해결할 문제 / 산업별 적용 / 솔루션·플랫폼 / 도입 사례 / 도입 절차 / 맞춤 진단

메인 순서: 고객 약속 → 6개 문제 카드 → 진단 CTA → 적용 사례 → 도입 절차 → 제품군 → 회사 신뢰 자료 → 상담.

기존 DT→DX→AI→AX 설명은 기술 접근법으로 유지하고, 구매 과정에는 ‘현황 확인→시범 적용→검증→구축’ 절차를 별도로 제시합니다.

담당자 업무 흐름

상담 요청 → 검토 대기 → 보완 질문 → 상담 완료 → 현장 진단 → 제안 제출 → 도입 / 보류 / 부적합

진단 답변·추천 이유·규칙 버전·고객 요청을 함께 전달. 담당자가 최종 구성을 수정하면 이유를 기록하여 규칙 개선에 활용합니다.

접수 확인과 회신 예정은 운영 인력·업무시간에 맞춰 정합니다. 자동 접수 안내와 실제 담당자 검토 완료를 구분합니다.

현재 React 홈페이지에서의 최소 구현 범위
  • Platforms.tsx의 8종 제품 설명을 정리한 카탈로그와 별도 추천 규칙을 작성하고, 문제별 진입·진단·결과 화면을 추가합니다.
  • PlatformModal.tsx → Contact.tsx의 제품명 전달 흐름에 고객 답변 요약·제안 구성·확인사항을 추가하는 방식을 검토합니다.
  • 현재 폼은 EmailJS 호출 코드가 있으나 실제 수신·업무 처리까지 이번 조사에서 검증하지 않았습니다. 출시 전 진단 정보가 수신 템플릿에 보존되는지 확인해야 합니다.
  • 초기에는 계정·견적 DB·CRM 신규 구축을 필수로 두지 않습니다. 상담 건수·담당자 수가 늘어나면 서버 접수와 상담 관리 도구를 연계합니다.
  • 공개 전 상담 정보의 수집·전송 항목과 목적을 실제 동작에 맞춥니다. 분석 이벤트에는 이름·이메일·자유입력 내용을 넣지 않습니다.
09

작은 출시, 실제 상담 검증, 이후 확장

일정은 기획 가정입니다. 콘텐츠·제품 담당자·개발자 각 역할의 참여와 자료 확정이 전제이며, 확정 견적이나 납기 약속이 아닙니다.

단계 / 일정 가정만들 것담당 역할다음 단계로 넘어갈 기준
준비 / 1주8개 제품의 제공 상태·적용 조건·사례·비용 항목, 6개 문제 분류 확정기획 + 제품 담당 + 영업미확정 기능이 상용 추천에 섞이지 않음. 초기 공개할 경로 선정
MVP / 2~3주문제별 진입, 6질문, 규칙 추천, 결과 요약, 상담 전달디자인 + 프론트엔드 + 상담 담당선택→결과→상담 내용 전달 전 과정 검증. 모바일·수정·실패 흐름 확인
제한 공개 / 2주잠재고객 인터뷰·실제 상담 적용, 추천 수정 이유 분석영업 + 제품 담당 + 기획고객이 제안 이유와 다음 단계를 설명할 수 있음. 담당자 중대 오추천 검토 완료
확장 / 검증 후승인 단가 기반 범위 견적, 사례 연결, 보고서, 상담 관리, 자유문장 보조성과에 따라 결정데이터 품질·단가표·운영 책임자 확보, 개인정보·연동 범위 확정
첫 공개 후보: 현장 업무·점검이 명확하고 한 구역에서 시작하기 쉬운 Smart FM 중심 ‘시설 운영 효율화’를 우선 검토합니다. 근거는 로컬 연혁의 개발 완료 기록과 업무 범위의 명확성입니다. 현재 데모·공급·지원 가능성을 확인한 뒤 최종 결정하며, 6개 경로 전체를 동시에 상용화할 필요는 없습니다.

출시 전에 확인할 실제 시나리오

  • 제품명을 모르는 고객이 문제만으로 결과에 도달한다.
  • 수기 운영과 기존 시스템 보유 고객에게 서로 다른 다음 단계가 나온다.
  • 안전·장비 요구나 정보 부족은 사전 검토로 분기한다.
  • 진단 답변이 변경되면 결과·저장 요약도 함께 바뀐다.
  • 상담 접수 성공·실패 시 입력과 추천 근거가 보존된다.
  • 담당자가 접수된 내용만으로 다음 질문과 담당 분야를 정한다.

성과 지표와 측정 기준

  • 진단 완료율: 유효 결과를 본 진단 세션 ÷ 시작한 진단 세션.
  • 상담 전환율: 접수가 확인된 상담 요청 ÷ 결과 조회 세션.
  • 유효 상담 비율: 문제·현장·후속 협의 의사가 확인된 상담 ÷ 전체 접수 상담.
  • 제안 전환율: 제안 제출 건 ÷ 상담 완료 건. 도입 전환은 별도 추적.
  • 추천 수정률: 핵심 구성이 바뀐 건 ÷ 검토 완료 추천 건. 수정 사유와 함께 해석.
  • 상담 준비 시간: 담당자가 자료 확인·질문 준비에 쓴 시간의 중앙값 비교.

출시 후 첫 4주를 기준선으로 수집하고 목표를 정합니다. 테스트·중복·스팸은 제외하며 전환 집계 기간을 고정합니다.

  3. components/Platforms.tsx:40–302 — 8개 제품군의 소개 범위. 제품 설명은 홈페이지의 주장으로 분류하고 현재 제품 운영 증거와 구분.
